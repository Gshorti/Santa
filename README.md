# Тайный Санта: сервер

Бэкенд Telegram Mini App для организации обмена подарками. Написан на OneScript с фреймворком winow, данные хранятся в PostgreSQL. Запускается через Docker.

## Быстрый старт

1. Скопируйте файл настроек и заполните его:

   ```bash
   cp .env.example .env
   ```

2. Откройте `.env` и впишите значения. Назначение переменных описано в комментариях `.env.example`. Обязательно нужны:

   | Переменная | Описание |
   |---|---|
   | `TOKEN` | токен бота от BotFather, по нему проверяется подпись `initData` |
   | настройки PostgreSQL | база, пользователь и пароль |

   Токен бота это секрет: не коммитьте `.env` в репозиторий.

3. Соберите и запустите:

   ```bash
   docker compose up -d --build
   ```

4. Проверьте, что всё поднялось:

   ```bash
   docker compose ps
   docker compose logs -f
   ```

## Миграции базы данных

SQL-миграции лежат в каталоге `migrations/` и применяются по порядку номеров. Применённые версии записываются в таблицу `schema_migrations`.

Применённые миграции править нельзя. Изменение схемы делайте новой миграцией.

Если миграции не запускаются автоматически при старте сервиса, выполните их вручную командой, предусмотренной в вашем проекте (например, отдельным сервисом в `docker-compose.yml`).

## Настройка бота и мини-апки

1. В BotFather создайте бота (`/newbot`) и получите токен.
2. Задайте адрес мини-апки через `/newapp` или кнопку меню бота (`/setmenubutton`). Адрес должен быть HTTPS.
3. Для приглашений по ссылке используйте формат `https://t.me/<бот>/<short_name>?startapp=<код>`. Значение `startapp` приходит клиенту в `start_param`.

## Авторизация запросов

Клиент передаёт сырую строку `initData` в заголовке:

```
Authorization: tma <initData>
```

Сервер проверяет подпись (HMAC-SHA256 с ключом, выведенным из токена бота) и свежесть `auth_date` (не старше дня). Идентификатор пользователя берётся только из проверенного `initData`, а не из тела запроса.
